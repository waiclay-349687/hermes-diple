# 前后端都要读写的数据，存进插件自己的 SQLite

完整版、已发批次、交接记录、审阅清单，这几类数据存进宿主为插件准备的 SQLite：`plugins.plugin_storage.plugin_db("<id>")` 打开的数据库文件，位于 `~/.hermes/plugin-data/<id>/data.db`，按 profile 隔离，开了 WAL。只有界面自己用的数据（每个会话的待发列表、设置）放在 `ctx.storage`。

选 SQLite 的原因有三条：
- 插件 API 和 AI 一侧的钩子、引用展开，可能是不同的模块实例，甚至是不同的进程，模块里的全局变量没法共享（XR1-08）；
- 「发送 → 送达确认」这一步要原子化，app 重启之后也不能丢；
- 审阅清单要按文件、状态、会话查询。

没选 JSON 文件：并发写要自己加锁，容易出错。没选 DuckDB：它面向分析，这里用不上。

两个插件各用各的库，不读对方的库。用户已同意。

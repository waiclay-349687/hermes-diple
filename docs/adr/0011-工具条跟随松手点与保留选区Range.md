# 聊天版：工具条跟随松手点（方案 B），浮层共用它的前沿，选区 Range 在显示时保存

出处：V3-T。调研 `A-工具条位置` 在 9 个场景里实测，方案 B（松手点右下方）到按钮的距离一律 45–46px，原来居中在选区上方的方案平均 96px。上游风险 N5 里有两条和这里相关：#144421（宿主约 1 秒后清掉聊天选区）和 #144170（会话中段的消息会卸载再挂载）。只改聊天版，core 和 desktop-kit 不动。

## 决定

1. **工具条位置是一个纯函数**：`place({ lines, pointer, backward, rtl }, size, viewport, avoid)`。输入是按行合并的选区矩形、松手点（键盘选区用 focus 端的插入点）、方向、要避开的图钉，输出 `{ left, top, side }`。偏移量照原型：横向 6px，纵向 4px。反向拖选放在松手那一行的上方。RTL 镜像。
2. **浮层和工具条共用前沿**：`placeEditor(rect, size, viewport, { lead, rtl })`。浮层默认在原文下方，前沿是工具条的前沿；没有工具条时用原文起头。前沿存成相对原文的偏移，滚动时跟着原文走。下方放不下时翻到上方。
3. **Range 在工具条显示时保存**。选区在没有用户输入的情况下被折叠时（宿主脚本），工具条保持显示，「标注」和 ⌘⇧E 把保存的 Range 放回选区再读。任何鼠标键、任何非快捷键的按键、`input` 事件、窗口失焦都会收起工具条，并丢掉保存的 Range。
4. **#144170 不加新代码**，只加回归。高亮层的 MutationObserver 会重新解析 Range，图钉跟随 `onChange` 重新测量。e2e 会覆盖同一节点插回和全新副本两种情况。

## 代价

- 宿主清掉选区后，按钮还在，但选区的高亮已经没了。用户能看到按钮，但看不到它对应的是哪段文字。按钮紧挨着松手点，一般不会认错。只要用户点一下鼠标或按一个键，按钮就会消失。
- 新的规则是「任何键都收起」，所以方向键也会收起按钮，以前只有打字、Esc 会。⇧+方向键扩选时，按钮会在选区停下约 300ms 后回来。
- 宿主用 `unicode-bidi: plaintext` 排版消息，所以 RTL 是按段落里第一个强方向字符判断的，不只看 `direction`。

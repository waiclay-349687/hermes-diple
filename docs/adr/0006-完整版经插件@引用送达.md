# 完整版通过插件 @ 引用送达，不走 pre_llm_call 加文字哈希

插件「摘录」在 Python 一侧注册 `@excerpt:` 前缀（`ctx.register_context_reference`）。

- **发送时**：显示版末尾带上 `@excerpt:<批次号>`。宿主在开始这一轮时展开它，调用 provider 的 `expand(批次号)`，把完整版作为 `--- Attached Context ---` 附进用户消息并持久化。桌面端重新加载对话时，会把这一段从气泡里剥掉。
- **为什么不用原方案**：原方案是 `pre_llm_call` 钩子，按显示版文字的哈希去取完整版。GPT 交叉审查发现它有三个问题：
  1. 文字哈希没法代表某一次发送（XR1-01）；
  2. 钩子注入的内容超过 10000 字就会被宿主截断，三条 4000 字的摘录就超了（XR1-04）；
  3. 只消费一次、重试、确认是否成功，这些都没有可靠的信号（XR1-03）。
- **新方案怎么解决**：
  1. 批次号明写在文字里，身份是确定的；
  2. @ 引用的上限是模型上下文的 50%，超过 25% 时宿主会给警告；
  3. `expand` 本身被调用，就是「AI 收到了」的回执，而且可以重复展开，重试安全（`agent/context_references.py`、`tui_gateway/prompt_turn.py`）。

## Consequences

- **插话（steer/interrupt）不会展开 @ 引用。**
  - 所以摘录**永远不跟着插话发出**。AI 正在回答时，列表的发送按钮会变成「回答完后发送」，由插件自己排队；那个会话的回答结束后，插件再提交。
  - 这时如果用户用主发送键插话，插话照常发出，摘录留在列表里，并提示「摘录会在下次发送时附上」。
  - 这里改了需求 01-#20 里「沿用插话/排队规则」的做法。用户 2026-10-24 授权「尽快交付成品、低风险的决定自己定」。
- **显示版末尾多一个小记号 `@excerpt:<批次号>`。** 气泡里会看到它（桌面端只把内置前缀渲染成小标签）。这也让批次在 Telegram 和命令行里一样可以追溯。
- **回应规则里的批次号就用这个号**，和 ADR 0002 里的 `b` 是同一个。

# 拆成两个插件：「摘录」和「摘录·审阅」，共用核心，用插件事件通信

用户决定做两个插件：**摘录**（`excerpt`，负责聊天摘录、待发列表、发送和回应标记）和**摘录·审阅**（`excerpt-review`，负责 md 审阅页和审阅清单）。助手原本推荐合成一个插件，因为两边共用摘录、待发列表和回应标记，拆开后要跨插件同步数据。

两个插件放在同一个仓库里。共用的纯逻辑（摘录模型、待发列表、完整版和显示版的生成、回应标记的解析和核对、重新定位）放在 `packages/core`，构建时分别打包进两个插件，运行时互不 import。插件之间只通过官方支持的插件事件通信：一方的后端调用 `broadcast_plugin_event`，另一方的前端用 `host.onEvent('plugin.<id>.<event>')` 订阅。每个事件的载荷都带版本号。

## Consequences

- 「摘录·审阅」依赖「摘录」：它的「加入待发」和「直接发送」都要交给「摘录」来完成。如果「摘录」没装或被关掉，这两个按钮会置灰并给出提示，审阅清单本身照常可用。
- 事件约定只有两条：
  - `plugin.excerpt-review.handoff`：把摘录交给待发列表；
  - `plugin.excerpt.batch.answered`：回报哪些批注已经得到回应，用来更新审阅清单里的状态。
  改动这两条约定的载荷时必须升版本号，两个插件都要兼容上一个版本。
- 前端发给对方插件的消息，都得先经过自己的后端转一道。前端之间没有官方支持的直连通道，`ctx.rest` 也只能访问自己的 `/api/plugins/<id>`。
- 2026-10-24 补充（XR1-07）：事件会广播给所有窗口，宿主不保证一定送达，所以交接必须有 handoffId，收件方先去自己的后端做原子认领（先到先得），再回执 `plugin.excerpt.handoff.receipt`。完整约定见 ADR 0007。

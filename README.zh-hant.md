# 圈批（Diple）— 在對話裡劃線、寫批註，交給 AI 逐條回應（Hermes 桌面端外掛）

在 Hermes 桌面端的對話裡劃出一段文字，可以附一條意見，攢成一批隨下一則訊息送出；AI 會逐條回應每一條意見，你可以在回答和原文之間來回跳轉。

> **名字的由來。** Diple（›）是古希臘抄本頁邊的標記，用來指向一行的注解，也是引號的前身；圈批 = 圈（劃線）+ 批（批註）。

> **非官方外掛。** 這是社群外掛，不是 Nous Research 或 Hermes Agent 專案製作、審核或支援的。

## 功能

- **選取即標註**：在任意一則聊天訊息裡選取文字，放開滑鼠後，「標註」按鈕立刻出現在放開處的右下方，緊挨著游標（也可以按 <kbd>⌘⇧E</kbd>）。即使 app 隨後清掉了選取範圍，按鈕照樣能用。標註會記住出處：哪個工作階段、哪則訊息、誰說的。
- **劃線與批註**：加進來的每一段都是一則**標註**。寫了意見的是**批註**（AI 必須回應），沒寫的是**劃線**（只作背景材料）。
- **在原文下寫意見**：小浮層在按鈕原來的位置開啟，也就是原文下方（下方放不下時翻到上方）。上面是原文（Markdown 已渲染），下面是意見框，底部是「儲存」「儲存並傳送」兩個按鈕，另有一個圖示按鈕「用目前選取範圍取代原文」。
- **原文上的圖釘**：標註過的原文加底色（批註另加底線），右上角釘一個編號圖釘。滑鼠停在圖釘上，浮出一張卡片，有三個按鈕：「編輯」（劃線是「寫意見」）、「複製」「刪除」；已傳送的只有「複製」。
- **輸入框上方的膠囊列**：儲存過的標註按工作階段排成編號膠囊，等你傳送。點膠囊回到原文；可以刪除、全部清除（可復原）、預覽；重新載入後還在。
- **「傳送 N 則 ▾」**：隨下一則訊息一起送出，或者點「傳送 N 則」只傳標註。▾ 選單裡有「直接傳送」和「複製給 AI」（Markdown，什麼都不送出）。
- **回應標記**：AI 在回應某則批註的段落前寫一個標記，介面上顯示成「↩ 批註 2」這樣的小標籤，點一下跳回原文。
- **漏答提示**：回答漏掉了某則批註時會提示（「批註 2 沒有回應」），一鍵「放回待發」。
- **跳回原文不閃**：原文不在畫面上才捲動，到達後保持加深，不閃爍。
- **忙碌時排隊**：AI 還在回答時，用「回答完後傳送」把這批標註排隊，這一輪結束後自動送出。
- **傳送前預覽**：看清對話泡泡會顯示什麼、AI 會收到什麼，並按宿主的上下文上限估算大小。

外掛介面支援 Hermes 桌面端的全部語言：**English、简体中文、繁體中文、日本語、العربية、Русский、Français、Deutsch、Español**（阿拉伯文由右至左顯示）。預設跟隨 app 的語言，也可以在外掛設定裡另外指定。傳給 AI 的說明文字在兩種中文介面下用中文，其他語言一律用英文。

## 安裝

外掛分兩半：桌面端外掛（`plugin.js`）和一個小的 Python 後端（`plugins/diple/`），兩者都要裝。下面指令裡的 `~/.hermes` 是你的 Hermes 主目錄；若使用具名 profile，換成 `~/.hermes/profiles/<名稱>`。

### 方式 A：下載 release

1. 從[最新 release](https://github.com/waiclay-349687/hermes-diple/releases) 下載 `plugin.js`、`plugin.js.sha256`、`diple-python-0.2.2.zip` 和 `diple-python-0.2.2.zip.sha256`，然後校驗：

   ```bash
   shasum -a 256 -c plugin.js.sha256
   shasum -a 256 -c diple-python-0.2.2.zip.sha256
   ```

2. 放到對應位置：

   ```bash
   mkdir -p ~/.hermes/desktop-plugins/diple ~/.hermes/plugins
   cp plugin.js ~/.hermes/desktop-plugins/diple/plugin.js
   unzip -o diple-python-0.2.2.zip -d ~/.hermes/plugins/
   ```

3. 啟用後端，然後重新啟動 Hermes 桌面端：

   ```bash
   hermes plugins enable diple
   ```

### 方式 B：從原始碼安裝

需要 Node.js 22 或更新版本。

```bash
git clone https://github.com/waiclay-349687/hermes-diple.git
cd hermes-diple
npm install
node scripts/install.mjs --home ~/.hermes --no-enable
hermes plugins enable diple
```

`scripts/install.mjs` 會建置 `plugin.js`，並把兩半複製到 `--home` 指定的 Hermes 主目錄（它從不自行猜測目錄）。裝完請重新啟動 Hermes 桌面端：Python 部分只在 app 啟動時載入。

## 用法

1. 在聊天訊息裡選取文字，點游標旁的「標註」（或按 <kbd>⌘⇧E</kbd>），編輯浮層在選取範圍下方開啟。
2. 需要的話寫一句意見，按 <kbd>Enter</kbd> 或「儲存」；意見為空就存成劃線。這一則會在原文上釘一個編號圖釘，並在輸入框上方出現一個膠囊。可以從目前或其他工作階段加任意多則。
3. 照常輸入並傳送訊息，或者點「傳送 N 則」（或按 <kbd>⌘⇧↩</kbd>）只傳標註。訊息下方的回執列（「已附 3 則標註 · 檢視 AI 收到的內容」）說明送出了什麼。
4. 在回答裡點「↩ 批註 n」標籤，跳回對應原文。如果有批註被漏答，在提示上點「放回待發」。

圖釘卡片上的「複製」：劃線只複製原文；批註複製成 Markdown——原文每行前加 `> `，空一行後是意見，和「本工作階段標註」裡「複製為 Markdown」的格式一樣。想把批註變回劃線，清空意見再儲存即可。

AI 正在回答時按 <kbd>Enter</kbd> 是插話，標註不會跟著插話送出；這時請用「回答完後傳送」。

### 快捷鍵

| 操作 | 預設 | 說明 |
| --- | --- | --- |
| 把選取內容加入待發 | <kbd>⌘⇧E</kbd> | 可在 app 的快捷鍵設定裡改綁 |
| 送出待發列表 | <kbd>⌘⇧↩</kbd> | 可改綁 |
| 在膠囊列裡傳送 | <kbd>⌘↩</kbd> | 焦點在輸入框上方的膠囊列裡時 |

## 設定

從命令面板（「圈批：設定」）或 app 的設定裡開啟。

| 設定項 | 預設 | 作用 |
| --- | --- | --- |
| 啟用圈批 | 開 | 總開關。關閉後快捷鍵、待發列表、底紋和回應標記的互動都停用；資料保留。 |
| 選取後顯示工具列 | 開 | 選取範圍旁的「標註」按鈕。關掉後用 <kbd>⌘⇧E</kbd> 或命令面板。 |
| 介面語言 | 跟隨 app | 跟隨 app，或九種語言之一（各以自己的名稱顯示）。影響外掛介面；傳給 AI 的說明文字在簡體中文 / 繁體中文介面下用中文，其他語言用英文。 |
| 安靜模式：原文只顯示圖釘 | 關 | 標註過的原文不加底色和底線，只在旁邊留編號圖釘。 |
| 傳送後保留標記 | 開 | 已傳送的標註在原文上保留淡化的標記，已回應／漏答也標在圖釘上。 |
| 快捷鍵 | — | 開啟 app 的快捷鍵設定，改綁兩個操作。 |
| 恢復預設 | — | 恢復預設設定（保留介面語言）。 |

## 運作原理

### AI 收到什麼

對話氣泡保持簡短：你的正文，加上每條標註一行（編號、出處、開頭約 40 字、你的意見），最後一行是 `@diple:<批次號>`。這一行是 Hermes 的上下文引用：這一輪送出時，外掛後端把它展開成**完整版**——每條標註的完整原文、出處、說話人和意見，以及簡短的回應規則（批註要逐條回應，劃線只是背景材料）。單段原文超過 4000 字時保留開頭和結尾各 1500 字。送出前點**預覽**、送出後點**檢視 AI 收到的內容**，都能看到兩個版本。

### 回應標記

回應規則要求 AI 在回應批註 1 和 3 的段落前寫 `::ann{b="<批次號>" n="1,3"}` 這樣的標記。Hermes 桌面端會渲染這類指令；外掛把它畫成「↩ 批註 1, 3」標籤，並核對哪些批註沒有得到標記。程式碼裡的標記不算。

### 資料存放位置

- 待發列表和送出狀態：Hermes 桌面端的外掛儲存（app 的本機儲存，鍵前綴 `hermes.plugin.diple.`）。
- 已送出的批次（用於展開 `@diple:` 引用、顯示 AI 收到的內容）：SQLite，位於 `~/.hermes/plugin-data/diple/data.db`。

設計決定記錄在 [docs/adr](docs/adr/README.md)，整體結構見 [docs/architecture.md](docs/architecture.md)。

## 隱私

資料都在你的電腦上。外掛本身不發出任何網路請求，沒有遙測，除了 Hermes 主目錄和 app 的本機儲存，不往別處寫任何東西。標註只會作為你送出的訊息的一部分到達模型服務商，和你自己輸入的文字一樣。

## 已知限制

主要幾條（完整列表和原因見 [docs/known-limitations.md](docs/known-limitations.md)）：

- 兩個視窗在同一瞬間寫同一個會話的待發列表時，可能遺失其中一次寫入。
- 會話忙碌時加入的標註，會對照產生它的那一輪來驗證；無法確定時保持「未驗證」，不去猜。
- 宿主輪換會話 id 之後（例如上下文壓縮），在新會話裡重新展開舊的 `@diple:` 引用會被拒絕。
- 還沒有右鍵選單入口：Hermes 桌面端沒有給外掛開放右鍵選單擴充點。

## 相容性

已在 Hermes Agent **v0.22.5 (2026.9.24)**、commit `bf0203a`（2026-10-22）、macOS 上測試。需要 Hermes 桌面端（只有 CLI 不會載入桌面外掛）。其他版本可能可用但沒有測試過，歡迎回報。

## 姊妹外掛：圈批·文檔

[圈批·文檔（Diple Docs）](https://github.com/waiclay-349687/hermes-diple-docs) 是這個家族裡負責文件的那一個：在 Hermes 桌面版開啟 Markdown 檔案，劃線、寫批註，標註跟著檔案保存。檔案改動後，每條標註會重新找回原文位置，並顯示待發、已發、已回應還是已解決。

兩個外掛都安裝時，在文件頁點「傳送」，文件裡的標註會進入本外掛該對話的待發列表，和聊天裡摘的標註排在一起，隨下一則訊息送出；AI 用同樣的編號標記逐條回應。不安裝它，圈批的功能也完全不受影響。兩者是獨立的外掛，各有儲存庫和發佈版本，可以只裝一個，也可以都裝。沒裝圈批時，圈批·文檔也能單獨使用，「複製給 AI」照樣能用；只有傳送到聊天才需要圈批。

## 與同類外掛的區別

官方精選目錄裡有一個相關的桌面外掛 **quote-ask**（`hermes plugins info quote-ask`）：選取文字後以 Markdown 引用的形式放進輸入框，輕量、不保存狀態。圈批面向審讀長回答：待發列表跨多次送出保留，每條意見帶編號、AI 必須回應，會核對漏答，回答和原文雙向連結，完整原文透過上下文引用送達而對話氣泡保持簡短。圈批改編了 quote-ask 的「選取範圍轉 Markdown」程式碼（MIT，見 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)）。兩者外掛 id 不同（`quote-ask` 與 `diple`），可以同時安裝。
